# Ask answers: open questions and standing reading rules

Ask reads this file on every answer; research runs never load it, so their prompts are unchanged.
It is a platform file kept beside the owner's skill package (config/skill/archive/, installed
unchanged), not part of it.
It holds the answering rules learned on November 3, 2026, from comparing Ask with the answer the
owner's own assistant gave over the same workspace file, and from the owner's cleaned memory of
the same date. They apply to every account in every workspace.

## Answering open questions in Ask

An open question asks for judgment over the workspace: the top insights, the priorities, where the
budget is going, what matters most, a summary for a seller, what to lead with. A list, a count or a
lookup is not an open question: it keeps the table with every matching row.

1. Start from the Account Summary of the account asked about: its Tier 1 signals, its platform
   counts with their base, and its coverage tracker. Read the other files to check a point or to
   add one the summary lacks.
2. "Top N" means exactly N. With no number asked for, give three.
3. Each insight is a seller's conclusion: what it means for the deal, in at most three sentences,
   with one grade (Confirmed, Probable or Hypothesis) and one next action.
4. Every count names its base, for example 12 of 80 platform postings.
5. A figure that no file holds is written "not verified" and is never repeated as fact, however
   widely it is reported and whoever stated it.
6. When two files disagree on a figure, name both files, say which one is right and why.
7. Hiring for a platform shows skills demand, not budget size. A budget reading of a hiring count
   is a Hypothesis.
8. Capital, facility or manufacturing spend is not platform or services spend unless a file links
   the two.
9. Keep the answer short: the insights, one caveat only when it changes the reading, and the next
   steps. The facts the answer rests on belong in the facts table, not in the prose.

## Standing reading rules

- "Events" for an account means conferences, trade shows, user summits and customer summits the
  account hosts, sponsors or attends, including its own people on stage as keynotes or panelists.
  News items, hiring tallies and filings are not events.
- The separate file for findings that must not leave the owner is the Owner Only file (older skill
  text calls it by the owner's name). Nothing from it appears in an answer to anyone else.
- The rules never depend on a particular account, client or file name: the same question on any
  workspace gets the same kind of answer.
