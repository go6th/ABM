# PR4 part A: quarantine bucket, local ClamAV, no signature stub, browser CRC32C (2026-11-04)

Part A prepares the infrastructure and the two ends of the checksum without changing the API: Terraform adds a separate `${name}-quarantine` bucket (uniform access, public access prevention, no versioning, same CMEK, CORS for the web origin with the resumable headers, 1-day delete rule; api may create objects and read metadata, worker may read and delete; `QUARANTINE_BUCKET` env on api and worker; the old `quarantine/` prefix rule stays on the documents bucket). `compose.yml` and `compose.replica.yml` get a `clamav` service (`clamav/clamav:1.3`, port 3310 in the compose network, healthcheck) and api and worker run with `DOCUMENT_SCANNER=clamd`, `CLAMD_HOST=clamav`. `SignatureScanner` and `scan_bytes` are deleted from `src/documents/scan.py`: `scanner_for` returns `ClamdScanner` when clamd has a host, otherwise `UnavailableScanner` in every environment, and the container default is now `clamd`; hermetic tests get `tests/fakes/scanner.py` (`FakeClamd`: EICAR infected, all else clean, no name rules) through an autouse fixture in `tests/conftest.py`. The browser (`web/lib/upload.ts`, `web/lib/crc32c.ts`) computes the file's CRC32C in 8 MiB pieces and sends `{"size_bytes", "crc32c"}` (base64 of the 4 big-endian bytes) with `POST /v1/documents/{id}/complete`; the current handler has no body parameter and ignores it. Part B (API verification, `QUARANTINE_BUCKET` use, `scan_failed`, abandoned-row job, signed-session creation in the new bucket, generated contract for the complete body) is not done.

Staging verification: (1) `terraform plan` shows only the new bucket, its IAM members and the env var on api and worker; apply per `docs/deploy/RUNBOOK.md` section 2.1a; (2) `gcloud storage buckets describe gs://ai-staging-quarantine` shows the 1-day rule, CORS and public access prevention; (3) `gcloud run services describe` for api and worker lists `QUARANTINE_BUCKET`; (4) locally `docker compose up -d clamav` becomes healthy, then an EICAR file upload is rejected and a `.py` or `.js` file is accepted, matching staging; (5) stop the clamav container and confirm an upload is not marked clean (part B turns this into `scan_failed`); (6) in the browser network tab the complete call carries `size_bytes` and `crc32c`.
