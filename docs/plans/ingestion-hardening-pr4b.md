# PR4 part B: quarantine store, size and CRC32C check, scan_failed, abandoned uploads (2026-11-04)

Part B puts part A's pieces to work. With `QUARANTINE_BUCKET` set the container gives `DocumentService` a second store: `start_upload` opens the resumable session in the quarantine bucket, `_scan` reads from it, copies a clean file into the documents bucket's content-addressed `raw_key` (server-side between two GCS buckets, streamed otherwise) and deletes it from quarantine; a document created before the bucket existed is found in the documents store as a fallback. `POST /v1/documents/{id}/complete` takes an optional `{size_bytes, crc32c}` body (`DocumentCompleteBody`, contract and web client regenerated); `complete` compares the stored object's size and CRC32C (GCS metadata; the local store computes it with `research_files/crc32c.py`) with what the browser reported, rejects `size_mismatch` / `checksum_mismatch` and deletes the object; a missing checksum skips only the checksum, and `import_file` computes its own while spooling. An unreachable scanner now gives the new status `scan_failed` (never read, quarantine object kept, `reject_reason scan_unavailable` kept for the message); the 5-minute sweep scans it again up to 3 attempts in all (`documents.scan_attempts`), then it stays `scan_failed` with "Upload it again later". `awaiting_upload` rows older than 24 h become `abandoned` through `documents.service.mark_abandoned`, run daily by the new worker route `/tasks/documents-abandon` and a Cloud Scheduler tick `documents-abandon` (02:20 UTC). Migration `0109_upload_states` (down_revision 0106) adds the two states, the counter, and relaxes `ck_documents_rejected_reason` (a reason is required on `rejected` and `scan_failed`, allowed on no other status). The trigger stays `complete` -> Cloud Tasks (decision Q5, no Pub/Sub); the sweep is documented as the safety net in `documents/service.py`. Terraform: the api's quarantine binding `quarantine_create` becomes `objectUser` (the api deletes the object on a mismatch) and the scheduler tick is added; nothing is applied.

Staging verification: (1) apply Terraform per `docs/deploy/RUNBOOK.md` section 2.1a with `-target=module.stack.module.scheduler` added: the plan shows the IAM role change on `quarantine_create["api"]` and one new Scheduler job `ai-staging-documents-abandon`; (2) deploy api and worker, run migration 0109 (health `EXPECTED_REVISION` is 0109); (3) upload a small file in the browser: the network tab shows the session on `storage.googleapis.com/upload/...ai-staging-quarantine`, the complete call carries `size_bytes` and `crc32c`, and after the scan the object is gone from `gs://ai-staging-quarantine` and present under `tenants/<tenant>/raw/<sha256>` in the documents bucket; (4) forge a mismatch (call complete with a wrong `crc32c` by curl with a dev token): the document is `rejected`, reason `checksum_mismatch`, and the quarantine object is deleted; (5) scale the clamav service down or point `CLAMD_HOST` at nothing on a throwaway revision: the upload ends `scan_failed` ("could not be reached ... will be tried again"), the quarantine object stays, and after the scanner is back the next sweep scans and reads it; after three failures it stays `scan_failed`; (6) start an upload and never send bytes, backdate `created_at` by 25 h in the database (or wait), run `gcloud scheduler jobs run ai-staging-documents-abandon`, and the row is `abandoned`.
