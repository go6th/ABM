# Prompt: build Observability (tracing per run, step timings, cost per account and per broker, failure dashboards, alerting and an on-call runbook), production grade

Paste everything below the line into Claude Code, opened in the project repo (built with the `account-intelligence-platform` skill).

---

Build the observability work package (DevOps with Backend). It has six parts: (1) a **telemetry contract** (catalogs of metrics, spans and log fields) and one instrumentation library that enforces it; (2) **tracing per run**, with the run id as the trace id; (3) **step timings** computed from durable events; (4) **cost per account and per broker** derived from the ledger; (5) **failure dashboards, SLOs and alerts as code** (Terraform for GCP, written and validated, never applied); (6) an **on-call runbook set** whose diagnostic queries are executable and tested. Observability must never leak tenant or private data, change how a run behaves, or become a second source of truth for money or run status. The "alerts" in this package are **operational** alerts for 6th's on-call; the product alerts sent to sellers are a different feature and are only measured here (alert freshness).

## 3. Anti-hallucination protocol (run time)

### 3.1 ObsGuard (each rule has a "lying scenario" test, section 8)
| # | Rule |
| --- | --- |
| O1 | **Telemetry never changes behaviour.** No exception, latency or backpressure from a tracer, meter, logger or exporter reaches a caller: bounded queues, non-blocking export with a timeout, drop-oldest with `telemetry_dropped_total{signal}`; no database transaction or lease is held while telemetry runs; a down collector leaves runs, API and settlement unchanged. Pure modules never import `src/obs/`; instrumentation lives at the edges (an import-graph test). |
| O2 | **One identity per run.** `trace_id_for(run_id)` is pure, total and injective (the UUID's 32 hex digits when run ids are UUIDs, else a documented hash) and is the same across the API, the scheduler task, every slice, retry and resume. Span ids are deterministic from `(run, stage, attempt, unit key)`, so a crash and resume never duplicates a span; the run's root span is emitted exactly once at terminal settlement (or by a closer when the worker died); trace context travels as identifiers only (`traceparent`; no content) through the outbox, the scheduler and Cloud Tasks. A child run has its own trace with a link to its parent. |
| O3 | **Allow-list at the sink, fail closed.** Every span attribute, log field and metric label passes the catalog: unknown keys are dropped and counted; values are checked **by shape** even for allowed keys (length cap, no URL with query or credentials, no email, no free text over the cap, no token or key shape, no control characters). Prompts, model outputs, page, posting and profile text, quotes, claim sentences, person names, company names, domains, secrets and tokens never appear: **identifiers only** (tenant, account, run, unit, stage, provider_code, route, alias). Exceptions are recorded as class, typed code and a message hash, never the message, locals or request body. |
| O4 | **Planted canaries prove it.** Distinct canary strings per class (prompt, document, secret, person name, domain) are planted in synthetic inputs, API bodies, provider payloads, exception messages and SQL parameters; after a full run and API session a scan over **every sink** (logs, spans, metric labels, error reports, run events, operator responses, console HTML, notification bodies, OTLP payloads) finds zero hits. A hit fails the build; in production a hit pages. |
| O5 | **Cardinality is bounded by construction.** Labels come from closed enums or bounded sets (stage, task kind, tier, outcome, failure class, provider_code, route, plan tier, region, graph version, severity); **never** tenant, account, run, person, domain, URL, user or free text; each metric declares a series bound that a simulation (1,000 tenants, 10,000 runs, hostile values) must stay under. Tenant and run dimensions live in traces, logs and database views. |
| O6 | **Money truth stays in the ledger.** Cost per run, account and provider is **derived** from ledger rows by an idempotent, watermarked, recomputable rollup (integer micro-USD, no float); telemetry never increments money on the hot path, so a replay or crash cannot double count. A reconcile job compares the rollup with the ledger (exact equality) and with the Credit cap v1 spend report; drift and **calls with unknown cost** are counted, exported and alerted, never treated as zero. Credits (tenant wallet) and dollars (broker spend) are separate series (defect 4). |
| O7 | **Timings come from durable events; traces are for diagnosis.** Step timings, queue and lease waits, critical path and idle time are computed from insert-only event tables (stage attempts, unit events, run events, ledger timestamps, gate, review), so they exist for unsampled traces and after a collector outage. A consistency test compares spans with events. A missing source is `SourceMissing(<name>)`, never a guess. |
| O8 | **SLIs come from truth.** Each SLO has a pure definition in `config/telemetry/slos.yaml` (good, total, window, exclusions, minimum sample, source tables); run states and events, request metrics, the ledger and the cache token counters are the sources; **no data is `NoData`, never 100% good**; late events are handled by an as-of watermark; human wait does not burn the run-duration SLI (D-58). |
| O9 | **Burn-rate alerts are multi-window and exact.** Burn = (bad / total in window) / (1 − target) in exact rational arithmetic; a page needs the long window **and** its short window above the factor (14.4x over 1 h and 6x over 6 h from the source; short windows are D-58); a minimum event count stops one failed request from paging; hand-computed oracles and properties (monotone, scale invariant, zero without failures). |
| O10 | **Silence is an alert.** Every service emits a heartbeat; missing data raises a telemetry-down alert, never a green board; the exporter pipeline's own health (queue depth, drops, export failures) is monitored by a watchdog that does not depend on the pipeline it watches. |
| O11 | **Isolation signals are layered.** (1) `rls_denied_total` counts permission errors from **writes** (SQLSTATE 42501); reads are filtered silently by RLS, so this is **not** a leak detector by itself (documented); (2) a **canary prober on synthetic tenants only** asserts that tenant A's session cannot see tenant B's planted rows and vectors; (3) the sink canary scan (O4). **Any prober leak or canary hit pages; RLS-denied writes page on a spike** over a configured baseline (the source says "any RLS-denied spike"; the threshold is configuration, `status: proposal`). The prober never reads a real tenant row. |
| O12 | **Stuck runs are observed, not repaired.** A read-only detector classifies QUEUED older than the reconciler's 60 s, RUNNING with no slice or unit event for a configured multiple of the 240 s slice, AWAITING_APPROVAL older than its 24 h timeout, expired leases and stale intents; each observation is an insert-only row and exported by state and age bucket; the reconciler stays the only repairer; a page fires if it has not fixed the condition within the configured bound (source: 5 minutes after recovery). A paused run is never "stuck". |
| O13 | **Calls are fully described but their content is not.** Attributes and metrics: task kind, tier, alias, token counts, cache-read, cache-write and uncached input tokens, cost micro-USD and its source, outcome, fallback and degraded flags, retry attempt, provider_code, operation, route. The cache-read ratio is computed on **cacheable calls only**, with a minimum volume, and alerts below 70%. Prompt capture is off (D-59). |
| O14 | **Every page has a runbook, an owner, a severity and a test.** Alerts and dashboards are generated from config; an alert on a metric missing from the catalog, or without runbook, owner, severity, `source` or `status`, or without a simulated incident that fires it, fails CI. Runbooks give symptom, impact, first checks (executable SQL in `docs/runbooks/queries/`, run by tests), mitigation, escalation, verification and follow-up, and never ask anyone to read tenant content, bypass RLS or run an unregistered script. |
| O15 | **Access and retention are explicit.** Telemetry and cost views are readable by the operator role only (identifiers and amounts, no content, through `operator_ro`); tenants never; trace links are built only from a configured base and still gated by the viewer's own access; support access reuses the logged, time-boxed grant; retention for logs, traces and rollups is configuration (`source: TODO`), run metadata stays at the sourced 13 months and the audit log is untouched. |
| O16 | **Changes are visible.** Resource attributes carry the service version (image digest), graph version, prompt and config hashes; deploys and flag changes emit markers; a pure canary verdict compares candidate and baseline SLIs (the version label is bounded by live versions) so a regression is attributable to a release. |

scripts/ check_telemetry.py check_runbooks.py gen_observability.py canary_scan.py

**Tracing.** Run root span (start = `created_at`, end = terminal time, emitted once); stage span per `(stage, attempt)`; unit span per work unit; tool and model spans as children; spans for the API request, the outbox relay and each slice. Run traces are always sampled (volume is low); API read paths use a configured ratio with errors kept (D-58). **Timeline:** `GET /operator/v1/runs/{id}/timeline` returns the event-derived timings with a deep link to the trace when `TraceLinkBuilder` is configured.
**Cost:** `costs.py` builds rollups by `(run, provider_code, route, cost_source)` and by account and plan tier; the operator API reads `operator_ro` views; exported gauges are aggregates by provider code and plan tier only.
**Dashboards (generated, all panels reference catalog metrics):** service health and SLOs; runs (state counts, durations, queue age, slices, resume success, stuck); providers (calls, errors, 429s, circuit state, adaptive limit, credits exhausted, cost by provider code); models (latency, tokens, cache ratio, fallback and degraded rate, verifier downgrade rate); **failures** (one panel per row of the "one owner per failure class" table: broker errors and Blocked reasons, evictions and resumes, slice budget, poison inputs, budget exceeded, reconciler re-sends, plus PARTIAL and FAILED ratios, gate defects by check, review queue age); security and isolation (RLS-denied writes, prober, canary hits, injection flags, auth and step-up failures); cost (operator project only).

## 6. Loops (all bounded, recorded, testable)
- **Exporter batch loop:** bounded queue, timeout, drop-oldest, drop counter. **Heartbeat and watchdog:** fixed period, never blocks. **Cost rollup:** incremental by watermark, bounded batch, idempotent upsert, resumable. **SLI job:** bounded windows, idempotent snapshots. **Stuck scan:** keyset pagination, bounded rows. **Canary prober and log scan:** one pass per run of the job, bounded targets.
- No retry loop over provider or model work is added; no loop repairs a run. Each loop records its exit reason and is listed in `docs/architecture/loops.md`.

11. **Isolation:** two tenants never read each other's rollups, snapshots or observations; the prober sees zero leaks on a correct database and **detects** a deliberately broken policy in a test database; `rls_denied_total` rises on a forbidden write and the documentation test confirms reads are not covered by it.
