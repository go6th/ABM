## Verified without finding (read and, where cheap, proved)

* Previous run choice is tenant- and account-scoped in SQL (`d.account_id`, `j.account_id`) and `load_previous` re-checks the account; the library import's deliverables have no `job_pipeline_runs` row and are skipped.
* Carried postings keep `text_ref`, `text_sha256`, sentences, classification, read flags (`model_copy`); the count chain (`read <= matched <= in_window <= deduped <= pulled`) holds because kept rows add their `raw_ref` to `pulled`. Carried rows are excluded from gap passes (`gap.py`), tested.
* `new_since_previous` over three researches: run 2 new rows are `True`; in run 3 they are carried and set to `False`, new rows of run 3 `True`. Semantics are "new since the previous research", consistent. A run 2 that never delivered is skipped (its paid work is repeated by design).
* Ledger: `active_only` is in the args hash, so the status refresh is a separate key, paid once and replayed on resume. Phase 1 and the pipeline use the same `FeedArgs(domain, since)` for the delta, one key. The research cache (job_openings TTL 3 days) can adopt an earlier run's active snapshot, so a second incremental run within 3 days refreshes statuses from stale data.
* All new writes in `jobs.repo`, `people.repo`, `pipelines.write_*`, `LinkArchive` use `tenant_txn`/`deps.txn`; `save_run` is one transaction; `link_archive` inserts are idempotent (`ON CONFLICT DO NOTHING`); `tech_stack_items` insert is guarded by an `existing` set.
* `ck_link_archive_url_is_http`: URLs with whitespace never reach the insert (`normalized()` returns None, p2.py), the 2048-cut `url` keeps the check; `url_hash` is computed from `url_normalized` as the CHECK requires.
* Migration 0089: the replaced trigger arguments are a superset of the old list (adds `employments`), the new erased CHECK is a superset, the level CHECK is widened to exactly the rubric levels; the down script keeps rows (NOT VALID). 0088 only widens a CHECK; deploy it before the code.
* People: exclusion runs before the level/stack path, so a security/privacy title never reaches `below_scope` listing; the band `below` person is kept off gap coverage and off profile pulls; export keeps `found_via` out of the denylist scan only by design.
* Heuristic: no catastrophic regex (terms are escaped whole-word patterns, `lru_cache`d), bounded by the 100,000-character stored text.
