# End-to-end test report, 2026-10-29

Scope: the whole workflow on a local stack with no real spend: sign in, start a research, get the
files, see the tables on the website, open archived links, re-research, stop and resume, tenant
isolation, logs. Tester: an agent that edited no repository source. Scripts and screenshots are in
`docs/audit/e2e/`.

## 0. How it was run (and three things that differ from the brief)

* Scratch database `ai_e2e` (migrated 0091 at the start, 0093 after the tree moved on, see D-12), seeded with
  `scripts/seed_replica_demo.py` (Meridian = tenant A, Northline = tenant B). API on 8094, worker on
  8093, web on 3009, all started through the preview tools. Launch entries added to
  `.claude/launch.json`: `api-e2e`, `worker-e2e`, `worker-e2e-scn`, `web-e2e` (+ `-capped` variants).
  No `.env` was sourced; only `APP_RW_PASSWORD` was read. Every model and provider key is blank.
* **Engine.** `RESEARCH_ENGINE=hermetic` (as in the brief) only records a finished run with no
  findings and no files (`replica/jobs.py:HermeticEngine`). To get files I used
  `RESEARCH_ENGINE=graph LLM_FAKE=hermetic CONNECTORS=hermetic`, i.e. the real research graph on the fake
  model and synthetic providers (the `compose.replica.yml` setup). Nothing leaves the process.
* **Worker.** A separate worker process is needed (the API posts slices to `WORKER_URL`; no Cloud
  Tasks emulator is required). It is `SERVICE_ROLE=worker ALLOW_UNAUTHENTICATED_TASKS=1`.
* **Scenario worker.** The stock hermetic posting text is 191 characters, under
  `jobs_v1.yaml` `minimum_text_length: 200`, so no posting is ever "read" and the Jobs sheet is always empty
  (D-6). For the Jobs/archive/new-flag tests I started the worker through
  `docs/audit/e2e/serve_scenario.py`, which swaps the hermetic job feed for five long postings (and an
  optional injected sixth read from a scratch file). It replaces handlers in memory; no source file was
  edited.
* **The source tree changed under the test** (another session was editing): `health.py`
  `EXPECTED_REVISION` went 0091 to 0093, a new migration 0093 appeared, and for a few minutes
  `archive.on_profile_host` did not exist. Results before ~15:50 UTC are against the tree as it was at
  15:10; later ones against the newer tree.

## 3. Defects

Severity: High = a file or table a client sees is wrong or missing; Medium = a flow fails or a rule is not applied; Low = polish. Line numbers are against the tree as it was when tested.

**D-1 (High) The Jobs sheet silently drops read postings that no fact cites.**
Reproduce: research Orion Systems with `serve_scenario.py` (5 long postings), open the Jobs sheet: 3 rows, Counts says 6 read and "Postings not listed (no posting link) 2", both withheld postings have links.
Cause: a posting needs a source code; source codes are only allocated for URLs a graded fact cites (`sources` has S-0004..S-0006 for `/s5 /s1 /s2`, none for `/s3 /s4`). `exports/readers/jobs.py:262-263` calls `ctx.code_or_withhold` and `readers/common.py:217-219` withholds on `missing_source_code`. Nothing registers every exported posting as a source (compare `agents/production/pipelines.py:382-420`, which does it for tech detections only). The label "no posting link" is also wrong: the cause is the missing source code. On a real run the same gap would drop every posting the reading model did not cite. Not seen on staging runs only if the model cites each one; worth a check there.

**D-2 (Medium) Archive "All" shows the page copy instead of the posting copy.**
Reproduce: `GET /v1/accounts/orionsystems.example/archive/list` gives `kind=page` for every posting URL with no status or location; `?kind=posting` gives the richer record (status at capture, location). The viewer for a posting link opens the page copy, so "Status when captured" and "Location" are blank in the index. Cause: the `link_archive` list de-duplicates by URL and prefers `page` over `posting` (archive list query behind `account_workspace.py` / `archive.py`; both `page` and `posting` rows exist per URL).

**D-3 (Medium) The website does not highlight the new-posting row.**
Reproduce: Orion run 3, open `/accounts/orionsystems.example/jobs`: first row "New since last research = Yes", computed background transparent; `GET /v1/accounts/.../sheets/jobs` rows have `fills: {}`. The file has fill `FFF9E6`. Cause: `replica/sheets.py:871-883` (`row_out`, file-shaped branch) never emits `fills`; only the grid path `file_tabs.py:934-937` does. The CSS class `fill-new-row` is ready (`web/components/accounts/cell-fill.ts`).

**D-4 (Medium) Resume of a stopped run stalls in the pull.**
Reproduce: start a research, press Stop after ~25 s, then `POST /v1/research/resume` (or the UI Resume after the run stops again). The new run replays the saved calls, then makes no calls: `no_progress` in 3 slices, ending PARTIAL "pull made no progress in 3 slices of 1650 s" (the message prints 1650 s although the local slice was ~63 s). Seen three times (caps on and caps off, `halcyonbay.example` run `9cef3cf5`: 0 calls, 3 slices, still RUNNING at the end of the test). A resume of a run that stopped with `no_progress` works with caps off (`stopcheck.example` run `7065ccb1`: 97 calls, finished). Also: coverage rows of one resumed run have `status NULL` for all 33 rows. Suspect the replay path with `resume_from` (`replica/jobs.py` GraphEngine, `runs/lifecycle.py`). The UI offers Resume only after a non-cancel stop, but the API accepts it for a cancelled run.

**D-5 (Medium, latent while caps are off) Run budgets are derived from earlier cheap runs.**
With caps on, the estimate and reserve come from the "last 3 finished runs": Zephyr full refresh reserved 29 credits ($1.45) and ended `BUDGET_EXCEEDED budget_cap`; the first UI refresh reserved 53 credits ($2.65) and stalled in `entity_lock` after 1 call; a Resume reserved 1 credit ($0.05) and stalled (`budget_usd 0.05`). A poor or stalled run lowers the next estimate. The refresh page also prints "Full refresh 4.2K tokens, $2.76" next to "Job postings only 300K tokens, $1.00". With `RESEARCH_CAPS=off` the same refresh finished normally, so staging is unaffected today; this returns when caps are switched back on.

**D-6 (Medium, test infrastructure) The hermetic provider can never produce a read posting.**
`connectors/hermetic.py` builds the posting text as 55 characters + `PAD` = 191, under `minimum_text_length 200` (`config/jobs_v1.yaml:9`). Result: Jobs, Archive-posting and the new-flag path cannot be exercised by the offline stack or replica demo (Zephyr: `read False`, `escalation failed`, Jobs sheet "None found" while Counts says "Postings naming a platform 1"). Also the hermetic organisation lookup returns no match, so no people ever exist.

**D-7 (Low) Row refs skip numbers.** The Jobs sheet refs are `J-0001, J-0003, J-0004, J-0006` because `exports/readers/jobs.py` takes `ref("J", i)` from the loop index before withheld rows are skipped; the website Ref column shows the gaps.

**D-8 (Low) Jobs workbook differs from the reference.** Extra sheets `Counts` and `Long text`, extra columns `Archived link`, `New since last research`, `Ref`, `Source code` (O to R) (intended, `jobs-workbook-done.md`), freeze `C2` where the manifest says `C9`, filter range follows the data (reference `A1:N1898`). Seniority shows the raw word `mid_senior`.

**D-9 (Low) People and Tech workbooks differ from the reference.** People has two extra columns `Ref`, `Source` (N, O); filters are data-sized; `Platform teams` has no autofilter (the manifest has none either). Confirmed stack is "None found" because the hermetic org lookup returns nothing.

**D-10 (Low) No Origin check on authenticated unsafe calls.** `POST /v1/accounts` with a valid cookie and CSRF token but `Origin: http://evil.example` returned 201; only the login route checks the Origin. Not exploitable without the token (SameSite=lax, `__Host-`), but weaker than the login rule.

**D-11 (Low) Archive index on a phone hides the View link.** At 390 px the table scrolls sideways inside its card and the Links column (View, original) is off screen; the page itself has no horizontal scroll.

**D-12 (Info) The working tree moved during the test.** Between 15:10 and 15:58 UTC `EXPECTED_REVISION` became 0093 and migration 0093 appeared; the worker restarted at 15:54 hit `ImportError: cannot import name 'on_profile_host' from 'account_intelligence.archive'` (`agents/production/payloads.py:21`) and left the research QUEUED for the account, so a second refresh answered 409 `refresh_in_progress` until I pressed Stop. Two lessons: a worker that fails to import leaves a QUEUED run that blocks the account, and the `ImportError` returned HTTP 500 to the task queue with no run failure recorded.

**D-13 (Info, dev only)** Console shows ~35 "Applying inline style violates CSP" errors per page, all from `nextjs-portal`, `next-route-announcer` and a Next dev script (`[style]` elements: 3, none from the app); expect none in a production build. Not verified on a production build.

**D-14 (Info) Message-less log lines.** Many INFO lines have `event: "log"` with logger `httpx`, `account_intelligence.connectors` or `exports` and no message text (the log catalogue strips messages), so a reader cannot tell what they report. No WARNING lines were seen.

**D-15 (Info) Cross-account look-alike sources in hermetic data.** Orion's archive contains `news.account.example`, `news.medium.com` and `adobe.com/trust.html` pages (from the synthetic cassettes); they are archived under the account and the entity lock did not reject them. Hermetic artefact, noted because "Key findings" then show bare platform names ("ServiceNow", "Salesforce") as Confirmed.
